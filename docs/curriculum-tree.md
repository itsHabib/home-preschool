# The curriculum tree — vision down, build up

*The one document that everything else must trace to. Planned for a child who is about to turn three; the horizon is their fourth birthday.*

## Why a tree

v1 was built week by week with no target above it, so every week was locally fine and globally aimless. v2 plans from the top: a vision with a date, strands with exit criteria, milestones with an observable check, units, weeks, activities. Every node states what its parent needs from it. Every leaf names the milestone it serves. Nothing gets built that does not trace up to the vision, and no milestone is allowed to have nothing serving it.

```
L0  Vision        one paragraph, one date, three outcomes
L1  Strands       5 strands, each with an exit criterion at L0's date
L2  Milestones    3–5 per strand, each with a 2-minute observable check
L3  Units         2–3 weeks each; a dinosaur family + a set of milestones
L4  Weeks         one dinosaur, one letter, five days
L5  Activities    one page + one card each; names its milestone
L6  Mechanism     kit templates, dino art library, generator code
```

Planning goes **down** (a node is planned only after its parent is), building goes **up** (a node is built only after its children are, post-order). Each level is a folder of small files, one per node, with the same schema, so an agent can be handed one node cold.

## L0 — Vision

By the child's fourth birthday:

1. **They read basic sentences.** Decodable ones, made of the sounds they have been taught: *The cat sat on the mat. Sam can dig.* They read them themselves, sounding out unfamiliar words, and can tell you what the sentence said.
2. **They identify numbers 1 to 10.** See the numeral, say it, and can show that many things. Count a set of up to 10 with meaning and compare two sets.
3. **Maybe: add within 5.** "Two dinos and one more dino is…" with objects, then with fingers. This is the stretch goal and gets cut before the first two do.

Dinosaurs are the costume for all of it, not a fourth goal. What the child learns about dinosaurs is vocabulary and a reason to show up.

## L1 — Strands and exit criteria

| Strand | Exit criterion at the fourth birthday | Serves |
|--------|------------------------------------|--------|
| **R. Reading** | Blends and reads CVC sentences of 4–6 words using the ~20 sounds taught; reads a 4-page decodable book aloud | Vision 1 |
| **N. Number** | Names numerals 1–10 on sight, counts out N objects to 10, says which of two sets has more; adds within 5 with objects | Vision 2, 3 |
| **L. Language** | Retells a story in order, uses 5+ word sentences, defines a dinosaur by feature and diet, answers "why" questions | Vision 1 (comprehension is half of reading) |
| **M. Motor** | Draws a line between two targets, traces letters with a crayon, cuts on a line with safety scissors, tripod-ish grip | Vision 1, 2 (every page and every letter formation) |
| **T. Thinking** | Continues an ABC pattern, sorts by two attributes, finds the odd one out with a reason, holds 4 items in "what's missing" | Vision 2, 3 and the "has to think" bar |

Two strands are new versus v1: Motor and Thinking. Both are there because the first round of feedback showed the ceiling was set by page design, not by the child.

## L2 — Milestones

Each milestone has a **check**: a two-minute thing a parent can do and write one line about. The checks reuse the `level-check.md` style. Order within a strand is the intended sequence; the target ages are targets and slip to the child, never the reverse.

### R. Reading

| # | Milestone | Check | Target age |
|---|-----------|-------|--------|
| R1 | Hears first sounds | "What does *sssun* start with?" 3 of 4 right | 3y 1m |
| R2 | Knows 6 sounds: s a t p i n | Point to each, they say the sound (not the name), 5 of 6 | 3y 2m |
| R3 | Oral blending | "c…a…t, what word?" 3 of 4 right | 3y 2m |
| R4 | Reads CVC words with letter tiles | Builds and reads *sat, pin, tap* from tiles, 3 of 4 | 3y 4m |
| R5 | Knows ~20 sounds incl. m d g o c k e u r h b f l | Sound check sheet, 16 of 20 | 3y 7m |
| R6 | Reads a decodable sentence | *The cat sat on the mat.* unaided, then says what happened | 3y 10m |
| R7 | Reads a 4-page decodable book | Reads it aloud at bedtime, retells it | 4y 0m |

*Tricky words* (the, on, is, I, a) are taught as sight words from R4 on, two at a time, because no CVC sentence survives without them.

## L3 — Units (the shape; the agents fill them)

A unit is 2–3 weeks, a dinosaur family, and a set of milestones it moves. The first quarter is planned now; later quarters are planned **after** the level check at the end of the previous one, because the milestone dates are targets and the child sets the pace.

| Unit | Weeks | Dinosaurs | Milestones moved |
|------|-------|-----------|------------------|
| U1 Plant-eaters with armor | 1–3 | Stegosaurus, Triceratops, Ankylosaurus | R1 R2, N1, L1, M0, T1 |
| U2 Plant-eaters with crests and spikes | 4–5 | Parasaurolophus, Iguanodon | R2 R3, N2 N3, L1 L2, M0 M1, T2 |
| U3 The meat-eaters | 6–8 | T. rex, Velociraptor, Spinosaurus | R3 R4, N3, L1 L2, M2, T3 |
| U4 The long-necks | 9–11 | Diplodocus, Brachiosaurus, Apatosaurus | R4 R5, N4, L2 L3, M2, T3 T4 |
| U5+ | planned after the Q1 level check | | |

Rules for units, weeks, and activities live in `design.md`: one dinosaur a week, its first letter is the letter, every activity has a decision the child makes, one page and one card a day.

## Level checks

Run `docs/level-check.md` before the first unit and again after each one. Keep the answers out of a shared repository; they are about your child. The newest check sets the starting rung, and its decisions are binding on the next unit planned.

## The plan node schema

Every node from L1 down is one file, `docs/plan/<L>/<id>.md`, with exactly these sections so any agent can be handed one cold:

```
# <id> <name>
Parent: <id>               what the parent needs from this node, in one line
Serves: <milestone ids>    leaves and weeks must list at least one
Goal: <one sentence>
Exit check: <observable, 2 minutes, parent can do it>
Children: <ids>            empty for leaves
Constraints inherited: <bullets copied down from ancestors>
Open questions: <bullets, or "none">
```

`node check-tree.mjs` (to be written at L6) walks `docs/plan/` and fails if any node has no parent, any week serves no milestone, any milestone is served by fewer than three activities across the planned units, or any exit check is missing.

## How the agents work it

**Down, one node per agent.** The root agent writes L1 and L2 (this file already does). For each L3 unit it spawns a unit agent with only: this file, `design.md`, the latest level check, and the unit row. The unit agent writes its unit node and one node per week, then spawns a week agent per week. The week agent writes five activity nodes. Each agent sees its ancestors and its siblings' ids, never the whole tree, so files stay small and the traceability lines are the only shared state.

**Up, post-order.** Building starts at L6: the dino art library and the kit templates the activity nodes ask for. Then each week's content is written into `content.json` form and rendered. Then the unit is checked against its exit checks by printing Week 1 and running it. Only then does the next unit get planned in detail. That is the DFS: plan a branch to its leaves, build the leaves, verify up, move to the next branch.

**Re-plan on evidence.** After each unit, run the milestone checks that unit claimed to move. Anything not met carries into the next unit; anything met early pulls the next milestone forward. The target ages in L2 are rewritten then, with the check result quoted.

## What this is not

It is not a school. Every activity is still 2–10 minutes, hands first, on the floor. The tree exists so the parents and the agents know why today's page exists, not so the child sits longer.
